# locoworker — independent static review

## Scope and verdict

Pinned revision: `a7a7cccc0f816f8441ac666b358ca2a7d1d3482a`. This is a research-stage Bun/TypeScript implementation, not an empty repository or a finished product. The [README:3-11](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/README.md#L3-L11) calls it an “agentic coding workspace” and explicitly retracts earlier isolation and feature claims. **Runtime NOT RUN**: this is a targeted source sample, not a complete repository audit or certification.

## Architecture and product boundary

The root [manifest:10-25](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/package.json#L10-L25) defines CLI, daemon, Hermes, dashboard, evaluation, testing and scan entry points. The CLI manifest depends on core, gateway and other workspaces; provider SDKs and Ajv are declared in the [core manifest:20-25](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/packages/core/package.json#L20-L25). The built-in dashboard and the experimental React/Vite dashboard are separate products; the desktop and daemon are separate entry points, not proven wrappers around the same execution path.

In the sampled core path, [queryLoop.ts:193-225](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/packages/core/src/queryLoop.ts#L193-L225) selects a tool, builds execution context, then calls `executeTool`. That executor validates input, applies the permission gate, requests approval where required, then executes. This establishes one static path, not every CLI, streaming, MCP, gateway or nested-agent path. The [dashboard router:68-102](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L68-L102) serves public HTML/health and calls `HttpGuard.authorize` before API routing. Its server entry point, guard implementation and live network behavior were not independently inspected.

## Findings ledger

- **LW-1 — High, confirmed documented limitation.** [README:17-29](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/README.md#L17-L29) says some writes are “gated by permission level (not a prompt)” and identifies the unsandboxed default. This describes intended operation, not a proven exploit or observed containment. An operator running untrusted projects or model-generated shell actions must not assume isolation. Document the authority boundary prominently and verify any selected sandbox with denial tests.
- **LW-2 — Medium, confirmed static / unverified risk.** [PermissionGate.ts:15-51](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/packages/core/src/permissions/PermissionGate.ts#L15-L51) rejects invalid levels and requires approval for flagged or dangerous tools. [executeTool.ts:75-113](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/packages/core/src/tools/executeTool.ts#L75-L113) passes the same mutable `input` to approval, a pre-tool hook and `tool.execute`; it does not snapshot it between those calls. A callback or hook capable of mutation could change what is executed after validation or approval; no such mutation or exploit was observed. Bind decisions to immutable validated arguments and test real entry points, including nested policy inheritance.
- **LW-3 — Medium, confirmed documented limitation.** [README:24-25](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/README.md#L24-L25) distinguishes the built-in dashboard from an “experimental” React/Vite UI. Fixture panels and stubbed integrations are documented elsewhere in that README; individual frontend components were not inspected. Misreading demonstrations as live health is a plausible operator risk, not an observed UI defect. Inventory and visibly label each fixture and unavailable action.
- **LW-4 — Medium, confirmed static / unverified risk.** [DashboardRouter.ts:78-100](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L78-L100) sends API requests to `authorize`, while `/health` and HTML precede it. [Lines 332-340](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L332-L340) store the bearer token in `localStorage`; [lines 88-90](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L88-L90) allow inline scripts. Token theft would require a separate script-execution or same-origin compromise; neither is established. Verify authentication, origin checks, token lifecycle and browser threat model instead of claiming the router is unprotected.
- **LW-5 — Medium, confirmed static / conditional risk.** [DashboardRouter.ts:274-289](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L274-L289) allows `build-graph` and spawns `run build:graph` with `cwd: projectRoot` and a filtered environment. If that project root is untrusted and supplies the resolved script, an authorized action may execute project-controlled code. Resolution, caller accessibility and actual environment filtering were not tested. Confirm Bun's resolution in an isolated fixture and avoid executing untrusted project scripts as a privileged dashboard action.

## Five-discipline assessment

**Correctness/code review.** The sampled loop reaches the shared executor; its own comment that all callers use the choke point is a claim, not independent proof. Schema validation occurs before the permission check, and a missing approver denies an approval-required action ([executeTool.ts:62-94](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/packages/core/src/tools/executeTool.ts#L62-L94)). Verify cancellation, hook failures, input mutation and alternate dispatch paths with actual callers.

**Automation/testing.** [CI:23-55](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/.github/workflows/ci.yml#L23-L55) specifies frozen install, scan, SBOM, typecheck, tests and two smoke checks; desktop is only typechecked, not packaged. [Historical run 41663295240](https://github.com/knarayanareddy/locoworker/actions/runs/41663295240) reports success at the pinned SHA. That is historical CI, not an independently rerun suite, coverage assessment or evidence of safe deployment.

**DevOps/operations.** Filesystem-backed sessions and optional daemon are described in [README:19-21](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/README.md#L19-L21). Restore correctness, daemon supervision, versioned release artifacts, signing and actual deployment configuration remain unverified. The router's graph action returns `started` after spawning; that response alone does not establish successful completion.

**OWASP/security.** Auth is delegated to an uninspected guard, and authorization granularity across dashboard, MCP and gateway remains unknown. Model responses, tool results and cloned projects cross injection boundaries; shell execution and URL fetch/SSRF protections need separate tests. Settings responses explicitly omit three credential-bearing fields ([router:263-271](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L263-L271)), but logs, other fields, bundles and provider transports were not audited. A frozen lock and scan are supply-chain controls, not proof of dependency safety. Transcript retention, file permissions and deletion need owner-defined policy and actual verification.

**UI/UX/accessibility.** Terminal approval must make the exact tool, arguments and consequences understandable; neither prompt nor interaction was tested. The built-in dashboard escapes rendered values ([router:332-355](https://github.com/knarayanareddy/locoworker/blob/a7a7cccc0f816f8441ac666b358ca2a7d1d3482a/apps/dashboard/src/DashboardRouter.ts#L332-L355)), but accessibility, token entry and error recovery require browser and keyboard/screen-reader checks. The separate experimental UI needs fixture labels before an operator treats it as telemetry.

## Production blockers and owner questions

Before any production decision, the owner must select trusted workspace assumptions, sandbox platforms, approved provider accounts and credentials, gateway exposure, data retention/deletion and recovery targets. Who authorizes real-tool actions and release signing? Which builds, desktop platforms and daemon environments are actually supported? No release, provider access, isolation, backup restore or accessibility claim is verified here.
